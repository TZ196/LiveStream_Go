# LiveStream 需求规格

基线 V1.1，2026 年 11 月 18 日。负责业务范围、需求编号和最终验收条件。阶段性能力由 [开发计划](../development-plan.md) 定义。

## 目标与使用者

系统用于学习和验证实时互动后端及其前端联调。使用者可以注册账号、创建房间、进入房间发送弹幕和连续点赞，并查看在线连接数及已持久化弹幕。开发者可以观察并发、积压、失败重试与恢复行为。

角色为访客、已登录用户和当前房间的房主。房主是房间所有者身份，不增加全局管理员或组织权限体系。详细规则见 [领域模型](domain-model.md)。

## 范围

V1 最终交付包含注册登录、公开直播间、文本弹幕、按点击累计的点赞、在线连接统计、历史查询、Kafka 异步持久化，以及本地运行、故障验证和性能报告。

不包含音视频推流、支付礼物、私信关注、推荐、AI 审核、私有房间、多实例 API、离线消息必达、复杂后台管理、Kubernetes 或服务网格。关闭后的房间仍可查询历史，房主可使用原房间重新开播。

## 功能需求

| 编号 | 需求 | 最终完成条件 | 首次交付阶段 |
| --- | --- | --- | --- |
| REQ-01 | 注册与登录 | 用户名唯一，密码安全保存；登录取得有期限的访问令牌，刷新保持登录且不延长有效期 | P1b |
| REQ-02 | 创建、结束和重新开播 | 用户创建自己的房间；只有房主能够结束和重开；沿用原房间，同方向重复操作不产生额外副作用 | P2 |
| REQ-03 | 房间查询 | 已登录用户分页查看房间列表和详情；明确区分开放与关闭 | P2 |
| REQ-04 | 进入与离开 | 合法用户通过握手加入开放房间；主动、异常退出均清理连接 | P3 |
| REQ-05 | 文本弹幕与审核 | 1–200 码点原文，经 AC 词库审核通过后进入独立 Kafka Topic；按用户分区，场次内尽力广播，其他房间不可见 | 本轮 P5 |
| REQ-06 | 点赞 | 点击立即反馈，按用户和场次合并 500 毫秒内的点击。每批按点击数累加，重试只计一批，同场总数每 200 毫秒合并推送。直播间公开本场点赞前 100 名，榜外用户只看自己的赞数 | P4 |
| REQ-07 | 在线连接数 | 同一房间按有效 WebSocket 连接计算；重复清理不重复减数 | P3 |
| REQ-08 | 弹幕历史 | 按房间及可选场次、数据库 ID 游标查询；与实时消息按 event_id 合并去重 | 本轮 P5 |
| REQ-09 | 操作确认与重试 | 服务端区分接受、拒绝和未确认；不向前端展示 Kafka 内部确认丢失；有限窗口内重试保留同一事件身份 | P3 初步，P4 点赞、P5 弹幕 |
| REQ-10 | 异步持久化 | Kafka 接受点赞事件后由独立 Worker 写库；事务成功后才推进消费进度，event_id 有唯一约束 | P4 点赞，P5 扩展 |
| REQ-11 | 故障恢复 | Worker 可重启续消费；Redis 投影可在停写窗口中恢复；不足以恢复时报告原因 | P6 |
| REQ-12 | 访问边界与限流 | 校验用户、房间状态、Origin、消息大小和频率；身份来自服务端认证 | P1b 起逐步交付 |
| REQ-13 | 前端状态 | 维护连接、重连及操作状态；不向用户展示 Kafka 内部确认丢失，未确认操作不伪称接受或失败；卸载页面释放资源 | P3 起逐步交付 |
| REQ-14 | 本地运行与部署 | 后端可在 WSL 调试；最终后端及中间件可容器化，前端可构建和访问 | P7 |
| REQ-15 | 性能与故障报告 | 记录硬件、参数、吞吐、分位延迟、积压及瓶颈，结果可复现 | P8 |

## 主要业务流程

用户注册并登录后取得访问令牌，查看房间列表或创建房间。进入开放房间时，前端先取得短时握手票据，再建立 WebSocket。每条弹幕、每个点赞批次各生成一个 request_id。点赞窗口从第一下点击计时，后续点击不延长窗口。已发批次的重试保留其 ID、场次与数量，服务端接收窗口内的完整点击数。

点赞从首次交付即以 Kafka 确认作为接受边界，服务端确认 Kafka 接受后返回 ACK。实时消费者汇总场次最新总数后广播，Worker 独立保存每一批的数量。ACK 不表示所有用户都已收到，也不表示数据库已经写入。客户端可先收到总数快照，再收到本批 ACK。页面以投影版本更新总数，以自己的 request_id 确认批次。

房主关闭房间后，新连接和新业务请求被拒绝，当前连接收到关闭原因并退出。已经准入的在途请求按照原接受流程完成，事件允许落库；已关闭房间不再进行业务广播。

## 非功能需求

| 编号 | 约束 | 验收方法 |
| --- | --- | --- |
| NFR-01 | 凭据保护、输入校验、权限隔离 | 越权、非法 Origin、过期令牌、注入文本和日志脱敏案例 |
| NFR-02 | 连接、队列、批次、重试有边界 | 慢客户端、过载、连接退出与 goroutine 回收测试 |
| NFR-03 | 事件可追踪，故障可定位 | request_id、event_id、分区位移及失败分类关联日志 |
| NFR-04 | 数据正确性优先于吞吐 | 重复、超时、重放、暂停恢复的计数和持久化断言 |
| NFR-05 | 本地过程可重复 | 配置样例、锁定依赖、迁移顺序和运行记录 |

本地单 Broker 不具备多副本容灾能力。V1 不承诺固定连接数、吞吐或端到端 Exactly Once；资源上限是保护配置，性能能力来自 P8 实测。

## 完成边界

最终交付必须覆盖所有 REQ 和 NFR。P3 的实时演示不代表历史查询已经完成，P4 点赞已计划包含 MySQL 持久化，仍不代表 P6 的历史查询和完整恢复已完成。完整追踪关系见 [验证矩阵](../verification/plan.md)。
