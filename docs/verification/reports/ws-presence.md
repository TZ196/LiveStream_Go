# 直播连接归属与在线人数验证

2026 年 11 月 27 日，任务分支 `feat/ws-room-presence` 基于 `main` 的 `9ce8c1f`。范围对应 ROOM-03、WS-01、WS-04、WS-06、UI-01。沿用 REF-01、REF-03、REF-04 的单写、短锁快照及有界队列，覆盖 ISSUE-05、ISSUE-09 的连接退出与依赖故障边界。

| 验证 | 实际结果 |
| --- | --- |
| 真实 API 与 WebSocket | 同房换窗口保持 1 人，跨房迁移后 HTTP 和推送人数一致。失败握手保留旧观看，过时票据和旧观看恢复被拒绝，正常重连保留观看编号。以实际 3 条连接的配额验证升级前拒绝与退出释放。 |
| 新连接的直播互动 | 点赞和弹幕收到 Kafka 接受确认，弹幕收到广播，Worker 最终写入 3 个点击和 1 条弹幕。 |
| Redis 暂停和重启 | 暂停期间新票据返回 503，普通就绪检查仍成功。旧连接在剩余租期耗尽时关闭。另一次真实重启确认 AOF 恢复了旧归属值，旧观看仍被拒绝，重新主动进入成功。 |
| 两个隔离 RoomHub | Redis 定向替换关闭旧连接，迟到清理保持新记录。省略替换通知后，旧实例在续期检查时摘除旧连接。 |
| 浏览器与协议 | Chromium 验证同房两页、旧页提示及禁用、新页人数、保留登录、主动重新进入与跨房切换。前端 28 项本地用例验证首屏门槛、人数版本、丢失关闭码和原请求重试等。 |

隔离环境使用 MySQL 8.4.13、Redis 7.4.7、Kafka 4.0.0 和全新 V9 库。API 与用例均以 race 构建，未观察到竞争报告。原始证据为本地 `/tmp/livestream-presence-ndrzu33y/` 的 `cases.log`、`browser.log`、`api.log` 和 `cleanup.log`。启动器 `backend/bin/presence/run.py` 及用例均仅保留本地。隔离进程、容器与卷已清理。

Go 格式、`go vet ./...`、`go test ./...`、`go test -race ./...`、四个 Go 入口构建，以及前端类型检查、构建和测试均通过。两轮通用 Go 测试各有 46 条通过结果，21 条按条件跳过。上表三组集成用例另在隔离环境显式执行。长时负载、实际容量和多 API 部署仍属独立验收。
