# 文档基线与职责分离决策

日期：2026 年 11 月 18 日。状态：纳入 V1.1 设计，待实现。

## 背景

工作区 docs 中的 Word 为 11 月 10 日版本，使用 Gin 和根目录 Go Module；Git 提交 29f9002 中的 11 月 17 日修订稿改用 Hertz、Vue 3 和 backend。AGENTS 与修订稿一致，同时维护两份可执行依据会导致选型及目录回退。

## 决策

以 [文档导航](../README.md) 中的 Markdown 文档作为唯一维护中的设计基线。按用户要求删除旧 Word 及归档目录，不保留并行版本。AGENTS 维护协作规则和确认过的技术边界，详细需求与契约由各自专属文档维护。

继承 Hertz、Gorilla Adaptor、Vue 3、单 API 和 Worker 架构，阶段性交付。P1 分成骨架和认证，Worker 在 P6 创建，检查命令随真实入口存在情况调整。

V1 不建立未定义业务用途的 room_members，也不引入 room_stats。在线连接与长期成员关系分离；公开房间没有持久成员资格或访问审计需求。房间关闭保留历史，不支持重新开启。

## 取舍

继续把所有内容放进 Word 会降低差异审查和跨文档引用的可操作性。复制全部细节到 AGENTS 会混淆协作约束与产品契约。因此采用分工文档并建立需求追踪，每项事实有一个维护位置。

新协议增加必要字段，并将业务 ID 对外表示为字符串；由于当前没有业务实现和既有消费者，不需要运行时兼容迁移。后续版本变更需同步受影响的接口和验收。
