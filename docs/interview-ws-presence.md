# 直播间在线人数与连接替换 · 面试问答

**功能描述**　同一个账号在新窗口成功进入后，旧窗口退出直播互动并保留登录。同房间换窗口仍算一人，跨房间则把这一人从旧房间移到新房间。

**Redis 和 Go 分别负责什么？** Redis 的 `ws:owner:{1001}` 记录用户、API 实例、连接、房间、场次、观看编号、代次、Redis 运行编号和是否已连接。Redis 用 Lua 确认归属。实际 WebSocket 和本机人数都在 Go RoomHub，广播直接使用本机连接。

**如何替换，又怎么防止旧连接误删？** 新窗口先验票据、查场次并完成握手，Redis 确认登记后，RoomHub 才停用旧连接并切到新连接。登记前失败，原窗口继续看。旧连接续期和清理都要匹配连接编号与代次，即使代次在键过期后从头计数，连接编号也不会重复。

**旧窗口断线后为什么抢不回来？** 主动进入创建新的观看编号，自动重连只能用原编号。服务端签票和最终登记都会检查归属。即使旧窗口漏收关闭通知，旧编号也恢复不了已被替换的观看。正常断开并完成清理后保留编号 30 秒，此时该连接已经退出人数统计。

**Redis 故障怎么办？** 归属租期 30 秒，每 10 秒检查并续期。Redis 短时不可用时拒绝新入房，已有连接只能使用上次确认的剩余租期。发现 Redis 重启后，AOF 里的旧记录也不能给旧连接续期。Ping/Pong 检测网络连接是否还活着，续租确认它是否仍有观看资格。

**人数和服务器连接上限有什么区别？** 人数只算已入房的有效账号。首屏给出当前数值，人数变化按秒合并推送。握手中、观看中和正在退出的连接都占用配额。256 是单实例默认保护阈值，实际容量要靠压测确定。

**能直接部署多个 API 吗？** 当前按单 API 使用。Redis 已能记录跨节点归属，Pub/Sub 用于定向通知旧节点，漏收后由续租发现。多实例上线前还要处理共享票据、跨节点直播广播、全局人数和接管时序。
