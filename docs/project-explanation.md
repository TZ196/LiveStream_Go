# LiveStream 项目讲解与工程证据

基线 V1.1。面向项目复盘和面试追问，规定如何把业务场景、设计取舍、边界、失败处理与验证证据连起来。具体协议仍由各专属设计文档维护，指标口径以 [验证设计](verification.md) 为准，完成状态以 [项目状态](status.md) 为准。本次新增的是讲解与验证要求，尚无业务实现或性能实测结果。

## 每个关键设计需要回答的问题

| 维度 | 需要讲清楚 | 应保留的依据 |
| --- | --- | --- |
| 场景 | 谁在什么情况下遇到什么问题；一次用户操作经过哪些环节 | 需求编号、正常流程和一个具体异常触发点 |
| 约束 | 当前部署规模、资源预算、正确性要求、允许的延迟和停写范围 | 已确认的需求、阶段承诺和资源边界 |
| 方案与取舍 | 最简单的方案是什么；当前选择解决哪一处问题；增加了哪些成本；什么条件下应换方案 | 对应设计；重要选择使用现有决策记录，记录替代方案和适用条件 |
| 边界 | 谁负责鉴权、状态、计数和提交；哪些操作原子完成；窗口、队列和权限如何限制 | 接口、状态机、事务与并发边界，以及拒绝条件 |
| 失败处理 | 如何发现故障；影响哪些能力；何时重试、暂停或隔离；恢复前如何核对；无法恢复时如何说明损失 | 故障案例、用户可见状态、重试预算和恢复条件 |
| 结果与证据 | 如何证明实现满足约束；实际测到什么；当前结论适用于什么条件 | 实现提交或 PR、测试命令、原始结果、指标口径和已知限制 |

按阶段选一至两个关键场景写成短记录，随代码和测试一起更新。用户负责确认业务取舍；实现负责人解释正常与失败路径；验证负责人核对证据和结论。一个人承担多个职责时仍分别完成这些检查。

## 结论的表达边界

- 设计结论写为“方案采用……，计划用……验证”；代码存在且可运行后再写“已实现”；具备测试或实验记录后再写“在……条件下验证了……”。
- 指标区分业务目标、保护阈值和实测结果。配置允许多少连接不等于已经测出相同规模的稳定处理能力，压测输入速率也不等于有效吞吐。
- 先交代这是本地学习与验证系统，并说明单 API Server、单 Broker 等部署边界。完整业务范围以 [需求规格](requirements.md) 为准，不把模拟故障写成真实生产事故。
- 对比方案时说明各自提供的保证。P3 内存接受与 P5 Kafka 接受的保障不同，仅比较延迟不能得出 Kafka 带来了多少同等能力下的优化收益。
- 对个人贡献，只陈述实际参与、理解并能复现的设计、实现和验证；能够沿着一条请求定位代码和解释失败处理，比背诵组件名称更重要。

## 示例：如何讲一次点赞重试

**场景。** 用户点击一次点赞，服务端可能已接受，浏览器却没有收到 ACK。如果把每次重发当成新动作，计数就会被放大；如果直接告诉用户“失败”，也可能与实际处理结果不一致。

**选择。** 设计使用 request_id 识别同一次用户动作，并以认证用户、房间、类型和请求身份生成稳定 event_id。同一动作重试保持身份，新的合法点击使用新身份。实时路径将去重与计数放在同一次原子操作中；Worker 将去重、业务写入和检查点放在同一事务中。Kafka Producer 幂等不替代这两处业务去重。

**约束和代价。** 请求可重试窗口、记录保留时间和日志保留策略必须相互匹配；记录需要内存预算。跨客户端、Redis、Kafka 和 MySQL 的整体过程不是一个事务，接受确认也不等于展示和落库完成。具体规则引用可靠性设计，不在讲解材料另定一套窗口或保证。

**失败处理。** 超时且无法证明未执行时保留 UNKNOWN，使用原身份有界重试。Redis 状态不完整时拒绝新写入；P6 按固定屏障核对持久化结果并重建。日志或数据库依据缺失时说明无法完成无损恢复，不能清零后继续接受点赞。

**验证。** IDEM-01 的同请求并发重试应只产生一次业务效果，COUNT-01 的不同合法请求应分别增加计数；再按 IDEM-03 注入确认丢失，按 REC-01 验证恢复。记录重试次数、唯一事件集合、计数差异、未决请求和恢复耗时。当前这些是预期断言，尚无实测成绩；P4 的验证不能代替 P5/P6 的 Kafka 与恢复验证。

## 阶段复盘与讲解准备

每阶段完成后，在项目状态记录一个简短条目：场景与需求编号 → 选择和替代方案 → 边界与故障处理 → 提交及验证入口 → 实测结论与限制。较长的实验报告在有实际实验时再建立，并由项目状态链接；重要设计理由继续放在对应决策记录中。

讲解可以先用一分钟说明项目用途、范围、本人完成内容和整体链路，再选择一个场景展开。追问时能回答“更简单的方案为什么不够”“哪一步失败后结果未知”“队列满了谁受影响”“数据从哪里恢复”“测量口径是什么”“扩到多实例需要重做哪些边界”。未实现或未测量的部分明确作为后续计划。
